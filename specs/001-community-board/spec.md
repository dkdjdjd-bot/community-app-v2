# Feature Specification: 커뮤니티 게시판

**Feature Branch**: `001-community-board`  
**Created**: 2026-02-14  
**Status**: Draft  
**Input**: 사용자 설명: "React + FastAPI 기반 커뮤니티 게시판 웹 애플리케이션"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 회원가입 및 로그인 (Priority: P1)

사용자는 이메일과 비밀번호로 회원가입하고, 로그인하여 JWT 토큰을 발급받을 수 있다. 인증된 사용자만 게시글 작성, 수정, 삭제가 가능하다.

**Why this priority**: 모든 기능의 기반이 되는 인증 시스템. 인증 없이는 게시글 작성/수정/삭제가 불가능하므로 최우선 구현 필요.

**Independent Test**: 회원가입 후 로그인하여 JWT 토큰을 발급받고, 해당 토큰으로 인증이 필요한 API에 접근할 수 있는지 확인.

**Acceptance Scenarios**:

1. **Given** 미가입 사용자, **When** 이메일/비밀번호로 회원가입 요청, **Then** 계정이 생성되고 성공 메시지 반환
2. **Given** 가입된 사용자, **When** 올바른 이메일/비밀번호로 로그인, **Then** JWT 액세스 토큰 발급
3. **Given** 가입된 사용자, **When** 잘못된 비밀번호로 로그인, **Then** 인증 실패 에러 반환
4. **Given** 미인증 사용자, **When** 인증 필요 API 접근, **Then** 401 Unauthorized 반환
5. **Given** 이미 가입된 이메일, **When** 동일 이메일로 회원가입 시도, **Then** 중복 에러 반환

---

### User Story 2 - 게시글 CRUD (Priority: P1)

인증된 사용자는 게시글을 작성, 조회, 수정, 삭제할 수 있다. 비인증 사용자도 게시글 목록 조회와 상세 조회는 가능하다. 게시글 목록은 페이지네이션을 지원한다.

**Why this priority**: 커뮤니티 게시판의 핵심 기능. 게시글 없이는 커뮤니티의 존재 의미가 없음.

**Independent Test**: 게시글 작성 → 목록 조회 → 상세 조회 → 수정 → 삭제 전체 흐름을 테스트. 비인증 사용자의 조회도 확인.

**Acceptance Scenarios**:

1. **Given** 인증된 사용자, **When** 제목/내용으로 게시글 작성, **Then** 게시글이 생성되고 ID 반환
2. **Given** 게시글 목록 존재, **When** 목록 조회 요청 (page=1, size=10), **Then** 페이지네이션된 게시글 목록 반환
3. **Given** 게시글 존재, **When** 게시글 상세 조회, **Then** 제목/내용/작성자/작성일시 포함된 상세 정보 반환
4. **Given** 게시글 작성자, **When** 게시글 수정 요청, **Then** 게시글 내용 업데이트
5. **Given** 게시글 작성자가 아닌 사용자, **When** 게시글 수정/삭제 시도, **Then** 403 Forbidden 반환
6. **Given** 게시글 작성자, **When** 게시글 삭제 요청, **Then** 게시글 삭제 (소프트 삭제)

---

### User Story 3 - 댓글 CRUD (Priority: P2)

인증된 사용자는 게시글에 댓글을 작성, 수정, 삭제할 수 있다. 비인증 사용자도 댓글 목록을 조회할 수 있다.

**Why this priority**: 게시판의 상호작용 기능. 게시글 기능이 완성된 후 추가하면 커뮤니티 활성화에 기여.

**Independent Test**: 게시글에 댓글 작성 → 댓글 목록 조회 → 댓글 수정 → 댓글 삭제 전체 흐름 테스트.

**Acceptance Scenarios**:

1. **Given** 인증된 사용자와 게시글, **When** 댓글 작성 요청, **Then** 댓글이 게시글에 추가
2. **Given** 댓글이 있는 게시글, **When** 댓글 목록 조회, **Then** 해당 게시글의 댓글 목록 반환
3. **Given** 댓글 작성자, **When** 댓글 수정 요청, **Then** 댓글 내용 업데이트
4. **Given** 댓글 작성자, **When** 댓글 삭제 요청, **Then** 댓글 삭제
5. **Given** 댓글 작성자가 아닌 사용자, **When** 댓글 수정/삭제 시도, **Then** 403 Forbidden 반환

---

### User Story 4 - Frontend UI (Priority: P2)

사용자는 웹 브라우저에서 회원가입, 로그인, 게시글 목록/상세/작성/수정, 댓글 작성/수정/삭제를 직관적인 UI로 수행할 수 있다.

**Why this priority**: 사용자가 실제로 서비스를 이용하기 위한 인터페이스. Backend API가 완성된 후 구현.

**Independent Test**: 브라우저에서 전체 사용자 흐름(회원가입 → 로그인 → 게시글 작성 → 댓글 작성)을 수행할 수 있는지 확인.

**Acceptance Scenarios**:

1. **Given** 웹 브라우저, **When** 회원가입 페이지 접근, **Then** 이메일/비밀번호 입력 폼 표시
2. **Given** 로그인된 사용자, **When** 게시글 작성 버튼 클릭, **Then** 게시글 작성 폼 표시
3. **Given** 게시글 목록 페이지, **When** 게시글 클릭, **Then** 게시글 상세 페이지로 이동
4. **Given** 게시글 상세 페이지, **When** 댓글 입력 후 제출, **Then** 댓글이 목록에 추가

---

### Edge Cases

- 빈 제목이나 빈 내용으로 게시글/댓글 작성 시도 → 유효성 검사 에러
- 존재하지 않는 게시글/댓글 조회/수정/삭제 시도 → 404 Not Found
- 만료된 JWT 토큰으로 API 접근 → 401 Unauthorized
- 매우 긴 제목(255자 초과) 또는 매우 긴 내용(10,000자 초과) → 유효성 검사 에러
- 동시에 같은 게시글 수정 시도 → 마지막 수정 우선 (last-write-wins)
- 삭제된 게시글의 댓글 조회 → 빈 목록 또는 404

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 이메일/비밀번호 기반 회원가입을 지원해야 한다
- **FR-002**: 시스템은 이메일 형식 및 비밀번호 강도(8자 이상)를 검증해야 한다
- **FR-003**: 시스템은 JWT 기반 인증을 제공해야 한다 (액세스 토큰, 만료 시간 30분)
- **FR-004**: 시스템은 비밀번호를 bcrypt로 해시하여 저장해야 한다
- **FR-005**: 인증된 사용자는 게시글을 작성(제목, 내용)할 수 있어야 한다
- **FR-006**: 모든 사용자는 게시글 목록을 페이지네이션으로 조회할 수 있어야 한다 (기본 10개/페이지)
- **FR-007**: 모든 사용자는 게시글 상세 정보를 조회할 수 있어야 한다
- **FR-008**: 게시글 작성자만 자신의 게시글을 수정/삭제할 수 있어야 한다
- **FR-009**: 인증된 사용자는 게시글에 댓글을 작성할 수 있어야 한다
- **FR-010**: 댓글 작성자만 자신의 댓글을 수정/삭제할 수 있어야 한다
- **FR-011**: 게시글 삭제 시 소프트 삭제 방식을 사용해야 한다
- **FR-012**: API는 적절한 에러 메시지와 HTTP 상태 코드를 반환해야 한다

### Key Entities

- **User**: 사용자 정보 (이메일, 해시된 비밀번호, 닉네임, 가입일시). 게시글/댓글의 작성자.
- **Post**: 게시글 (제목, 내용, 작성자, 작성일시, 수정일시, 삭제여부). User와 1:N 관계.
- **Comment**: 댓글 (내용, 작성자, 게시글, 작성일시, 수정일시). User와 1:N, Post와 1:N 관계.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 30초 이내에 회원가입을 완료할 수 있다
- **SC-002**: 게시글 목록 조회 응답 시간이 500ms 이내이다
- **SC-003**: 게시글 작성부터 목록 반영까지 2초 이내이다
- **SC-004**: 비인증 사용자의 보호된 리소스 접근 시 100% 차단된다
- **SC-005**: 모든 CRUD 작업이 적절한 에러 처리와 함께 동작한다
- **SC-006**: Frontend에서 전체 사용자 흐름(가입→로그인→글작성→댓글)을 완료할 수 있다
